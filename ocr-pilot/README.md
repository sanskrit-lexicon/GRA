# H5146 — Hellwig OCR пилот: 1 страница Cologne-скана gra

_Created: 19-09-2026 · Last updated: 19-09-2026_

## Ключевая находка: пайплайн Хелльвига не существует

Хендофф называет «OliverHellwig/sanskrit — CNN line-detection + recognition, лучший
публичный санскрит-OCR». Проверка (web + GitHub, 19-09-2026) показала:

1. У `OliverHellwig` на GitHub ровно один публичный репозиторий —
   [sanskrit](https://github.com/OliverHellwig/sanskrit) — метрический анализатор
   стиха, OCR-кода там нет; Wayback CDX по всем URL `github.com/OliverHellwig*`
   знает только этот репозиторий.
2. Единственная публикация Хелльвига по OCR —
   [Applying the OCRopus OCR System to Scholarly Sanskrit Literature (2009)](https://doi.org/10.1007/978-3-642-00155-0_21),
   код не выпущен.
3. «SanskritOCR» Хелльвига — закрытая платная Windows-программа (ind.senz, €129);
   её сайт `sanskritreader.de` припаркован на продажу. CLI/моделей нет.
4. Реальный публичный CNN-пайплайн, который бенчмарка́т Ind.senz —
   [ihdia/sanskrit-ocr (IndicOCR, CVPRW 2020)](https://github.com/ihdia/sanskrit-ocr):
   TF1.5, на Apple Silicon не запускается без docker; TF2-инференс v2-SavedModel
   не верифицирован — в 45-минутный бюджет не помещался.

## Замена (документированная)

Лучший публичный санскрит-OCR 2026 — дообученная VLM:
[`snskrt/qwen2-5-vl-sanskrit-ocr`](https://huggingface.co/snskrt/qwen2-5-vl-sanskrit-ocr)
(Qwen2.5-VL-7B + Sanskrit OCR corpus). Взят GGUF
`mradermacher/qwen2-5-vl-sanskrit-ocr-GGUF:Q4_K_M` (5.5 GB) под ollama 0.34.1,
нативно на arm64.

## Метод

1. Страница: `pg_0587.pdf` из [sanskrit-lexicon-scans/gra](https://github.com/sanskrit-lexicon-scans/gra)
   (страница 0587 — раздел корня √dā, самая плотная по деванагари среди
   нечётных страниц-кандидатов: 118 `{@...@}`-спанов) → `pg0587.png` 1700×2600 (sips).
2. Эталон: `csl-orig/v02/gra/gra.txt`, страница 0585→[Page0587]-разметка;
   деванагари = k1-заголовки (SLP1→Deva) + все `{@...@}`-спаны (IAST→Deva).
   `extract_gt.py` → `gt_page0587.txt` (695 симв. с пробелами), нормализовано до 506.
3. Распознавание: `POST /api/chat` ollama, изображение base64, промпт
   «Transcribe all Devanagari text…». Два независимых прогона.
4. CER: `cer.py` — Левенштейн по деванагари-потокам (NFC, без пробелов/данды).

### Систематика ошибок

1. **Коллапс полноты (главное):** модель выхватывает 1–3 изолированные формы
   (धाक्षतः, धक्षतः, दाग) и игнорирует остальную страницу — двухколоночная
   плотная вёрстка 1873 г. на уровне целой страницы не сегментируется.
2. **Ловушка CLI:** `ollama run <model> <prompt> <img>` молча НЕ привязывает
   изображение — модель возвращала стих из обучающего корпуса (शुभान्मुने…)
   за 6–12 s. Работает только chat-API с явным base64-изображением.
3. Дублирование и нестабильные висла́ги (॥ / ।) в выводе.

## Вердикт (цель хендоффа)

**Нет — в текущем виде OCR не заменяет ручную транскрипцию Cologne-сканов gra.**
CER 0.986 на уровне страницы означает фактически «текст не извлечён».
Осмысленный следующий шаг — порезка на строки (line-crops, как в IndicOCR v2)
или VLM-проход по строкам; это отдельный юнит, бюджет страницы-пилота исчерпан.

## Ограничения

1. Эталон — деванагари, *заявленное* в gra.txt; часть печатных форм оцифрована
   римской транслитерацией и в эталон не попадает (GT — нижняя граница).
2. Одна страница (0587), одна модель (Q4_K_M), разрешение 1700×2600.
3. Акценты (UDÁTTA/ANUDÁTTA) в эталоне сохранены, в распознавании — нет.
